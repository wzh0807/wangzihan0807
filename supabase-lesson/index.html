建好一个云端数据库
再让 AI 直接替你建表

传统流程是「装数据库 → 写 SQL → 建表 → 写接口」。这节课换个玩法：在 Supabase 建一个空项目， 把它的 MCP 地址接进 Trae，之后建表、插数据、开权限，全都用一句话让 AI 去做。

网页建空项目→MCP 接进 Trae→一句话让 AI 建表→前端调 REST 取数

0先弄懂三个名词一张表看懂谁干什么

层次是什么谁来干
Supabase 控制台网页端：SQL Editor、表编辑器、API Keys建项目时用一下，之后基本不用
MCP让 AI 能「远程操作」Supabase 的协议，一个项目一个专属 URL装一次，长期有效
Agent Skills（可选）教 AI「Supabase 该怎么用」的知识包装一次，AI 建表更规范
一句话记住：别再自己写 SQL 建表了，把 Supabase 的 MCP 地址喂给 AI，让 AI 直接在你账号里建库建表。

1开工前确认三件事少一件都会卡住

  1. 有 Supabase 账号：打开 https://supabase.com，右上角 Sign in，GitHub 或邮箱登录均可。
  2. 有支持 MCP 的 AI 编程工具：本课用 Trae（CodeBuddy 也可以），MCP 在「插件市场 → MCP」里管理。
  3. 知道免费版两条硬限制：一个组织最多 2 个免费项目；项目 7 天不活跃会被自动暂停。
答辩前一天务必去 Dashboard 看一眼项目是否还在线。显示 Paused 就点恢复，等一分钟即可。

2创建一个 Supabase 项目约 3 分钟

登录后进入 Dashboard，点左上角组织名旁的 New project，或直接访问 supabase.com/dashboard/new。

字段怎么填说明
Organization选自己的组织（标注 FREE）没有就新建一个
GitHub (optional)跳过课程项目用不上
Project name英文，如 wzh-project避免中文在 URL / 命令里出问题
Database password点 Generate a password，立刻复制保存只显示一次，丢失只能重置
Region选 Auto建完不能改
Data access勾 Enable Data API 与自动授权，不勾 RLS课程先用服务端 Key 访问

等 1–2 分钟状态变成 Healthy 后，记下三个值：

要记的东西长什么样后面用在哪
Project URLhttps://xxxx.supabase.co前端调 REST 接口
project-refURL 里那串小写字母拼 MCP 地址
数据库密码上一步保存的那串连接数据库、重置时用

3生成自己的 MCP 配置一人一个，不能照抄

项目首页往下滚，点 Get connected → MCP（或顶部 Connect 按钮切到 MCP 页签），复制配置里的 project_ref。下面填进去即可生成 Trae 用的 JSON：

{
  "mcpServers": {
    "supabase": {
      "url": "https://mcp.supabase.com/mcp?project_ref=你的project_ref"
    }
  }
}
键名别搞错：Supabase 网页给的是 "servers"，Trae 项目级 .trae/mcp.json 用的是 "mcpServers"。 粘完发现列表里没有 supabase，先回来检查这个键名。

4在 Trae 里装好 MCP 并授权多数人卡在授权这一步

  1. 打开 Trae「设置 → MCP」（在「插件市场」下面），确认顶部「启用项目级 MCP」已打开，这样才会读取 .trae/mcp.json。
  2. 把第 3 节生成的 JSON 交给 AI 写入 .trae/mcp.json，或在「插件市场 → MCP → + 添加 → 手动配置」里粘贴。
  3. 列表里出现 supabase 且带 ⚠ 前往验证，点它跳到 Supabase 授权页。
  4. 确认标题是 Authorize Trae、组织是你自己的、权限包含 Database 等，再点绿色 Authorize。
别在终端里裸跑 npx skills add supabase/agent-skills，那样会装到全局；给 Trae 用要加参数： npx skills add supabase/agent-skills --agent trae。
授权走 OAuth：不需要手动生成 Access Token，也不需要把数据库密码给 AI；授权一次长期有效。

5接好之后怎么用：说需求就行建表交给 AI

把下面这段发给 Trae（把主题换成你的作业主题），AI 会通过 MCP 在你的项目里执行 SQL：

用 supabase 帮我建一个「高级网页设计课堂实践」的数据库：
1. 建 3 张有关联的表，字段和类型你定，表名用英文小写并以 wzh_ 开头
2. 给每张表开启 RLS，并加一条「允许匿名读取」的策略，写入只允许 service_role
3. 每张表插入 8 条中文模拟数据（贴合作业主题）
4. 建完把表结构、字段说明和对应的 REST 接口路径整理给我，前端要用

验证 MCP 是否真通了，就问一句：

查一下我 Supabase 项目里现在有哪些表，把表名和字段列出来
接口是自动生成的：建完表就能用 https://xxxx.supabase.co/rest/v1/表名 取数（请求头带 apikey）。

7验收清单与课堂任务能跑 + 能讲清

  • Supabase 项目状态是 Healthy
  • 数据库密码、Project URL、project-ref 已记录
  • MCP 地址里是自己的 project_ref
  • Trae 的 MCP 列表里 supabase 是绿色对勾
  • Supabase 后台已点过 Authorize
  • 问 AI「我有哪些表」能返回真实结果
  • Table Editor 能看到表，REST 接口能返回数据
⭐ 任务一 · 跑通最小闭环建空项目 → 拿 MCP 地址 → 接入 Trae 并授权；问「我有哪些表」能返回结果即完成，截图存证。
⭐⭐ 任务二 · 让 AI 建三张表围绕作业主题建 3 张有关联的表，每表 8 条中文数据，开 RLS 并给匿名只读策略；截图 Table Editor，整理 3 条 REST 地址。
⭐⭐⭐ 任务三 · 前端取数 + 答辩用 fetch 调 REST 把数据渲染成卡片列表；准备三个答辩问题。
提交前把敏感信息打码：数据库密码、完整 project-ref、带 apikey 的请求头、授权页里的账号名，一律改成 XXXX。
