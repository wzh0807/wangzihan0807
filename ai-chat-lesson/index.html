第二步：用硅基流动 Key 做「AI 聊天」

王子涵 · 学号 0807 · 在已完成的全栈项目上加一个页面和一个接口

AI 聊天 · 独立成包

1这一步在做什么

前面的《全栈项目初始化》已经把前端页面、Node.js 后端、MySQL 数据库跑通了。这一步不重新起项目，而是在那套项目上：

  • 把硅基流动的 API Key 写进后端 backend/.env；
  • 后端新增 POST /api/chat，把浏览器的消息转发给大模型；
  • 前端新增聊天页面，把多轮对话的 messages 数组整体发给后端；
  • Key 只留在服务器端，前端代码里永远看不到明文 Key。

页面里不保存、不展示你自己的 Key。示例中一律写成 sk-****。

2先验一次 Key 通不通（强烈建议）

在命令行直接打一次硅基流动的接口，能分清「Key 有问题」还是「我的代码有问题」。

curl --request POST ^
  --url https://api.siliconflow.cn/v1/chat/completions ^
  -H "Content-Type: application/json" ^
  -H "Authorization: Bearer YOUR_API_KEY" ^
  -d "{\"model\":\"deepseek-ai/DeepSeek-V4-Flash\",\"messages\":[{\"role\":\"system\",\"content\":\"你是一个有用的助手\"},{\"role\":\"user\",\"content\":\"你好，请介绍一下你自己\"}]}"

成功时会返回一大段 JSON，里面有 "content":"你好！我是…" 这样的中文回答，说明 Key 和额度都没问题。

3跟做五步

  1. 写 Key：backend/.env 增加 SILICONFLOW_API_KEY=sk-****，不要加引号、不要留空格；
  2. 写接口：POST /api/chat 接收 { messages: [...] }，用 Key 转发到硅基流动，返回统一格式 { code, msg, data }；
  3. 写页面：输入框 + 消息气泡，发送后把用户这句话 push 进 messages；
  4. 多轮对话：把模型回复也 push 进 messages，下次请求带上完整历史；
  5. 测试与记录：先问「你好」，再问「我刚才问了什么」，能答出上一句就说明上下文生效。

完整代码见 三级项目/frontend/ai-chat.html 与 backend/wzh_apiController.js（含后端转发逻辑）。
